# Route Meshy work by where credits vanish

On the Pro plan, Meshy's web app and API draw from **one shared credit pool**, but they price the same work differently. The gap is not in generation. The API is equal to or cheaper than the web app for creating models: Meshy 7.1 textured costs 30 on the API and 33 to 35 on the web, where Ultra 2K is the default. The gap is in everything after generation. **Standalone remesh, rigging, preset animations and format conversion cost 0 on the web but 5, 5, 3 per clip and 1 on the API**, and **the web app adds 4 free retries per task**. The API has no free retries. For reroll-heavy work, those retries matter more than every other difference combined. This project's own ledger confirms the shared pool. The balance fell from 1,900 to 1,775 after 125 credits of API calls (one multi-image-to-3d at 30, three image-to-3d at 30, one rig at 5), and the web app then showed 1,775 too. Automating the web UI with an agent in your own Chrome is **not explicitly banned, but it sits in a grey zone**. Meshy's Acceptable Use Policy lets it disable accounts for "unauthorized automated or scripting processes", and its docs name the API and MCP server as the sanctioned automation route. The cost-efficient strategy has three parts. Generate in batches on the API, where it is cheapest, and bake remeshing into the generation call. Do rigging, animation and reroll-heavy hero work on the web at human pace, preferably with a person at the controls. Fix rerolls upstream with clean concept art, mesh-only first passes and settings tuned for a hand-painted look rather than PBR realism.

## The web app charges for creation and the API charges for everything after

The prices are not the same across the two surfaces, despite Meshy's tutorial claiming "equivalent tasks cost the same" ([Meshy credits guide](https://www.meshy.ai/tutorials/meshy-credits-guide)). Meshy's own web-app pricing table lists **Remesh 0, Rigging 0, and Animate 0 per clip** ([Docs: web-app pricing](https://docs.meshy.ai/en/webapp/pricing)). The API price list charges **Remesh 5, Rigging 5, Animation 3 per action (up to 10 per request), and Convert or Resize 1** ([API Pricing](https://docs.meshy.ai/api/pricing.md)). Downloads in every format are free and unlimited on Pro in the web app ([Help: credit costs](https://help.meshy.ai/en/articles/10000507-how-many-credits-does-each-generation-task-cost)). The API only offers format changes through the 1-credit Convert endpoint, although fetching the formats a task already produced is free. One partial offset favours the API: a 5-credit API rig **includes walking and running clips at no charge** ([Rigging API](https://docs.meshy.ai/api/rigging.md)).

Generation runs the other way. A live inspection of the Pro workspace on 31 October 2026 read these labels next to the Generate button:

| Operation | Web app (live UI label) | API |
|---|---|---|
| Meshy 7.1, Standard geometry, mesh only | 20 | 20 |
| Meshy 7.1, Ultra 2K geometry (web default), mesh only | 25 | 25 (20 + 5 Ultra) |
| Meshy 7.1, Standard, 2K texture | 33 (documented as 30; anomaly) | **30** |
| Meshy 7.1, Ultra 2K, 2K texture (web default) | 35 | 35 |
| Smart Topology T2.5, mesh only / textured | 5 / 15 | 5 / 15 |
| Meshy 6 Lite | 10 | 5 (15 textured) |
| Split at generation / Auto Split | +10 | 10 |
| Retexture | 10 (15 at 8K) | 10 (15 at 8K) |
| UV unwrap | 5 | 5 |
| Concept image, Nano Banana Pro | 9 per image | 9 (nano-banana and 2-lite: 3) |

Sources for this table: the live workspace and [Help: credit costs](https://help.meshy.ai/en/articles/10000507-how-many-credits-does-each-generation-task-cost) for the web column, and [API Pricing](https://docs.meshy.ai/api/pricing.md) for the API column. The web app quietly upsells. On paid plans Meshy 7.1 "starts at Ultra 2K, so the default cost is 25" ([Docs: web-app pricing](https://docs.meshy.ai/en/webapp/pricing)). Anyone who clicks Generate without switching to Standard pays 5 more for micro-geometry a hand-painted game throws away. Pro's pricing page also advertises "Unlimited AI image generation", yet the UI charged 9 credits per Nano Banana Pro image ([Pricing](https://www.meshy.ai/pricing)). Whether any image model is actually free on Pro remains unverified.

The web app's biggest economic lever is retries. Pro includes **"4 free retries per task (web app)"**, and each asset tile shows an "x4" counter ([Pricing](https://www.meshy.ai/pricing)). On the API, every resend is a new charge, and create endpoints have no idempotency key ([llms.txt](https://docs.meshy.ai/llms.txt)). Five attempts at a textured 7.1 character cost **150 credits on the API but 33 to 35 on the web**. Meshy has not documented what a retry reuses, such as the seed, settings or input, so treat each retry as a fresh roll of the same inputs.

The project's first API run exposes a hidden saving. All four generations ran with `should_remesh: true` and `target_polycount` set to 20,000, 5,000 or 3,000, and each still cost exactly 30. **Remeshing requested inside the generation call is free**. Only the standalone Remesh endpoint costs 5. Settling the polycount at generation time removes the most common post-processing charge on the API. The same run also left room for savings. `enable_pbr: true` costs nothing extra in credits, but it adds metallic, roughness and normal maps that work against a hand-painted shader, along with 30 to 60 seconds of generation time ([Task Lifecycle](https://docs.meshy.ai/api/task-lifecycle)). Leaving `image_enhancement` at its default of `true` lets Meshy "redraw" the input, and "details can change" ([Web-app Image to 3D](https://docs.meshy.ai/en/webapp/image-to-3d)). Clean concept art should disable it.

Billing rules apply equally on both surfaces. FAILED tasks are refunded. Deleting a PENDING task refunds it. An IN_PROGRESS task cannot be cancelled and is charged ([Errors](https://docs.meshy.ai/api/errors.md)). The old free test-mode API key was retired on 16 September 2026, so integration tests should mock the API rather than hope for a sandbox ([Deprecations](https://docs.meshy.ai/api/deprecations.md)). API outputs are deleted after 3 days for non-Enterprise customers, while the web library keeps assets persistently ([Asset Retention](https://docs.meshy.ai/api/asset-retention.md)). The MCP server adds no cost. Meshy states that "MCP tool calls make the same REST calls and use credits at the same rate" ([AI Integration](https://docs.meshy.ai/api/ai.md)). Pro's API allows 20 requests per second and 10 concurrent tasks ([Rate Limits](https://docs.meshy.ai/api/rate-limits.md)).

## Browser automation is tolerated by silence, not by permission

No clause in Meshy's Terms of Service (updated 19 September 2026) names bots, scraping, browser automation or AI agents. The full §2.6 use-restriction list covers reverse engineering, resale, account sharing, competitive products, malware and "interfere with any parts of the Service", but it has no anti-automation item ([ToS](https://www.meshy.ai/terms-of-use)). The relevant text sits in the older Acceptable Use Policy, dated November 2024: Meshy "may disable accounts" for **"Using unauthorized automated or scripting processes (such as bulk or automated uploading of content through a script)"** ([AUP](https://www.meshy.ai/acceptable-use-policy)). The policy never defines "unauthorized", but Meshy's docs make the sanctioned route clear: "Automation: Web app No / 3D Agent Limited / API Full", and "the API suits automation, batch processing" ([Choose web app, Agent or API](https://docs.meshy.ai/en/webapp/guides/choosing/integration)). An agent clicking the workspace UI is therefore automation outside the named channels, and Meshy can reasonably call it unauthorized.

Several factors cut the other way. The penalty language is discretionary ("may disable", "reserve the right to suspend"), and Meshy commits to "reasonable steps to provide you with written notice" first ([ToS §5](https://www.meshy.ai/terms-of-use)). The AUP's own example targets bulk scripted uploading, not a single account holder working at human pace. Account sharing is not triggered either, because the user remains the account holder and is "fully responsible for all use" under §1.2. The real exposure comes from motive. Automating the web app specifically to collect zero-credit rigs, remeshes and animations instead of paying API prices is the arbitrage Meshy's pricing split implicitly protects. At scale, it could be read as an attempt to "commercially exploit Meshy" ([AUP §4](https://www.meshy.ai/acceptable-use-policy)). The worst documented outcome is suspension. Fees are "non-cancelable and non-refundable" ([ToS §4](https://www.meshy.ai/terms-of-use)), so remaining credits would in practice be lost, although no clause says so outright.

The stakes are modest, which clarifies the decision. At the prices above, a fully animated character costs about 65 credits through the API: 30 to generate, 5 to rig and ten animation clips at 30. The same character costs about 33 on the web. The saving is roughly 30 credits per character, or about 3% of a Pro month. That does not justify unattended, high-volume UI automation. It does justify doing rigging, animation and retries on the web by hand, or with an agent at human pace while the user watches. Meshy's own **3D Agent** is an official in-app conversational path with web pricing, free retries and per-action credit approval ([3D Agent](https://docs.meshy.ai/en/webapp/3d-agent)). The official **Godot bridge** (Pro and above, with no API key and no credits) moves web-app models into the engine without any scripting ([Meshy for Godot](https://docs.meshy.ai/en/webapp/plugins/godot/introduction)).

## Eighteen web-only features, five of which matter for this game

The public API now covers nearly all generation and post-processing ([llms.txt](https://docs.meshy.ai/llms.txt)). What remains web-only is mostly interactive editing. Five web-only features matter for an MMORPG pipeline.

**Texture Edit** offers masked AI retexturing, a healing brush for seams, stamp, solid paint and decals. The API's Retexture replaces the whole texture and has no mask parameter. Saving edits requires a paid plan, and the per-edit cost is undocumented ([Texture Edit](https://docs.meshy.ai/en/webapp/guides/texture-edit)). **Custom Pose** sets an exact joint-level stance before generation, whereas the API's `pose_mode` accepts only `a-pose`, `t-pose` or empty ([Web Image to 3D](https://docs.meshy.ai/en/webapp/image-to-3d)). **Meshy Edit** adds, removes or replaces a mesh region for 20 credits on high-poly Meshy 6 and 7.1 models ([FrameSixty review](https://framesixty.com/meshy-ai-3d-review/)). **Rigging modes beyond humanoid** include Quadruped Dog and Smart Rig (Beta) for other creatures, while the API rigger documents humanoids only ([Web rigging guide](https://docs.meshy.ai/en/webapp/guides/3d-model/rigging); [Rigging API](https://docs.meshy.ai/api/rigging.md)). Finally, the **Animate browser** offers 500+ presets, multi-clip "All Added" export and a skeleton-template choice such as Mixamo ([Animate](https://docs.meshy.ai/en/webapp/guides/animate)).

The rest have no bearing on this game pipeline: 3D Scenes (which cannot export to a game engine), AI video, the 3D Agent's image inpaint and skills, image style presets, batch-of-10 generation UIs, persistent asset library management with labels, UV and printability inspectors, DCC and slicer bridges, Community/Discover, Meshy Shop printing, several Creative Lab categories, team per-member web credit limits, and the free website file converter ([3D scenes](https://docs.meshy.ai/en/webapp/guides/scene-video/scene-compose); [AI image generation](https://docs.meshy.ai/en/webapp/guides/image/ai-image-generation); [Assets](https://docs.meshy.ai/en/webapp/guides/platform/asset-management); [Web changelog](https://docs.meshy.ai/en/webapp/changelog)). One gap runs the other way. The web docs say Meshy 7.1 "isn't available in Text to 3D", but the API accepts `meshy-7.1` there ([Docs: web-app pricing](https://docs.meshy.ai/en/webapp/pricing); [Text to 3D API](https://docs.meshy.ai/api/text-to-3d.md)).

## Smart Topology for volume, Meshy 7.1 for faces and silhouettes

The October 2026 lineup is `meshy-7.1` (what `latest` resolves to), `meshy-6`, `meshy-6-lite`, and the Smart Topology models `meshy-t2` and `meshy-t2.5`. T1 "lowpoly" and meshy-5 are retired, and meshy-7 is deprecated ([Deprecations](https://docs.meshy.ai/api/deprecations)). Meshy 7.1 is the detail model, built for "organic characters with expression, anatomy, and skin folds" and multi-part objects whose parts stay separate ([Web Image to 3D](https://docs.meshy.ai/en/webapp/image-to-3d)). Smart Topology generates a clean triangle mesh directly at a chosen face count, for 5 credits: **T2.5 up to 30,000 faces with "sharper detail for game assets", and T2 up to 15,000 with "natively separated parts"** ([Image to 3D API](https://docs.meshy.ai/api/image-to-3d)). Meshy 6 has one niche that matters for this art style. It is the only model on which `remove_lighting` takes effect, and both 7.1 and `latest` ignore the flag ([Image to 3D API](https://docs.meshy.ai/api/image-to-3d)). Meshy 7.x always strips baked light, so `meshy-6` with `remove_lighting: false` is the only API path that might preserve painted highlights from concept art. No source has tested it, so it needs a pilot.

A hand-painted look puts detail in the texture on chunky forms, which pushes most settings in one direction. **Ultra geometry is wasted**, because 7.1 Ultra bakes "engravings, stitches, weaves and scales" into the mesh ([Meshy 7.1 launch](https://www.meshy.ai/blog/meshy-7-1-launch)) and decimation to game budgets erases it. **PBR maps fight unlit and toon shaders**, so base color only (`enable_pbr: false`) suits Godot unshaded or toon materials and Three.js `MeshToonMaterial`. **2K textures are enough**. Hand-painted textures are low-frequency, so downscale to 1K or 512 and compress with KTX2 or Godot VRAM compression. Retexture's best model is `meshy-7`, which means 7.1 itself is rejected there, so single-pass 7.1 texturing from the concept image is probably more faithful for characters than a later style-image retexture ([llms.txt](https://docs.meshy.ai/llms.txt)). No source compares the two directly. Meshy's own budget guide puts PC characters at 20k to 50k triangles, props at 5k to 15k, and environment pieces at 10k to 50k. Mobile AAA budgets are about half that ([Game Assets guide](https://docs.meshy.ai/en/webapp/guides/use-cases/game-assets)). A stylized MMO running in Three.js should aim near the mobile figures.

Rigging is the fragile step. The API rigger "works well only with standard humanoid (bipedal) characters", accepts at most 380,000 triangles, needs the face pointing to +Z, and returns 422 when pose estimation fails ([Rigging API](https://docs.meshy.ai/api/rigging.md)). Meshy's checklist points to one cause above all, self-intersection: "a cape drags the spine, a sword generated in-hand deforms with the arm" ([Auto-rigging tutorial](https://www.meshy.ai/tutorials/character-auto-rigging-workflow)). The modular design already solves this. Generate base bodies bare, without tails, shells, capes or held items, and attach those parts to bones afterward. The same tutorial notes that A-pose "gives more natural shoulder skinning" than T-pose. That suits MMO loops that keep the arms down. Use T-pose only when bulky sleeves fuse to the torso. Independent reviewers warn that "chunky cartoon proportions break the auto rig" ([Techraisal](https://www.techraisal.com/blog/meshy-ai-builds-a-game-ready-3d-character-in-60-seconds/)). Hooves, digitigrade legs and oversized heads should be expected to need manual weight fixes.

## Rerolls are an input problem, and mesh-only passes make them cheap

Most rerolls trace back to the input image. Meshy's checklist asks for at least 1024 × 1024 PNG with no JPEG artifacts, a plain white or transparent background, the subject filling 70 to 90% of the frame with nothing touching the edge, and even diffuse light, because "shadows bake into the texture" ([Help: Better Image-to-3D results](https://help.meshy.ai/en/articles/15723519-how-to-get-better-image-to-3d-results-in-meshy)). Perspective distortion warps proportions, so near-orthographic views win. Multi-object scenes make "the AI merge the objects into one distorted mesh" ([Web Image to 3D](https://docs.meshy.ai/en/webapp/image-to-3d)). Multi-view input (1 to 4 images, front first; with 7.1 the order of the rest "doesn't matter") ranks highest for back-side accuracy. Meshy recommends it when single images produce "flat faces, inaccurate proportions, or artifacts on the back" ([Multi-Image to 3D API](https://docs.meshy.ai/api/multi-image-to-3d); [Help: pose, face and hand issues](https://help.meshy.ai/en/articles/16102152-fix-character-pose-face-and-hand-issues-in-meshy)). Multi-view costs the same as single-image generation, so for characters it is cheap insurance. All views must share style, lighting and scale, or the seams will mismatch.

Prompting follows Meshy's formula of **subject + material + art style + technical constraints**, with the most important words first, one object per prompt and at most 800 characters ([Prompting guide](https://docs.meshy.ai/en/webapp/guides/prompting)). There is no negative-prompt field. Exclusions go inline ("no background elements, no text"), and "'Stylized' or 'cartoon' yields cleaner topology" than "realistic" ([Web Text to 3D](https://docs.meshy.ai/en/webapp/text-to-3d)). Pose should come from `pose_mode` or the web pose toggle, because "simply typing 'T-pose' … is not a reliable way to control pose" ([Help: pose, face and hand issues](https://help.meshy.ai/en/articles/16102152-fix-character-pose-face-and-hand-issues-in-meshy)). Thin parts are the persistent failure. Meshy "still fuses fine detail such as hair strands and window grids" ([FrameSixty review](https://framesixty.com/meshy-ai-3d-review/)), so exaggerate thickness in both the concept and the prompt: thick blades, solid rope, large open hands. A base-body concept prompt that applies all of this reads: *"[race] [class] base body, full body, A-pose, arms slightly away from body, hands open, feet apart, symmetrical, stylized hand-painted fantasy style, chunky readable proportions, flat even lighting, front view, orthographic, centered, plain white background, no props, no cape, no tail."* Avoid naming commercial games in prompts and describe the look instead.

The cost lever is sequencing. On 7.1, mesh-only (20) followed by Retexture (10) ties single-pass textured generation (30) at one attempt and wins from the second. On T2 and T2.5, five per mesh attempt plus 10 for the texture beats 15 per attempt as soon as you reroll once. The pipeline should therefore reject cheaply. Generate a 3-credit concept image and QA it. Run a mesh-only pass with `multi_view_thumbnails: true` for front, side, back and left renders ([Image to 3D API](https://docs.meshy.ai/api/image-to-3d)). Texture only accepted geometry. Then rig and animate. The exception is a character whose texture must match the concept closely. There, single-pass 7.1 texturing, or Multi-Image with `texture_image_urls`, keeps the 7.1 texture path that Retexture cannot reach. Run those generations on the web, where the free retries absorb the rerolls.

## Conclusion

Meshy's two price lists encode a deliberate split. Creation is priced roughly evenly, and the web app subsidises iteration and finishing. The cheapest pipeline exploits that split through placement rather than automation. Batch-generate props and environment pieces through the API at 5 to 15 credits with polycount baked in. Send characters and heroes, which need retries, rigs and clips, through the web, where those steps cost nothing. The ToS ambiguity matters less than it seems because the money at stake is small. About 30 credits per animated character does not justify an unattended bot, and a person clicking Rig and Animate captures nearly all of it with no policy risk.

The project's first 125 credits also point to two configuration fixes that cost nothing to adopt. Turn off PBR and image enhancement for clean hand-painted concept art. Pin `ai_model` explicitly so output does not drift when `latest` moves. The open questions are empirical, not contractual: whether meshy-6 with lighting preserved beats 7.1 for painted light, how well T2.5 handles trees and attachments, and how often stylized bodies rig on the first try. A 5-credit Smart Topology pilot answers most of them for the price of a single 7.1 character.

## Recommended routing

Costs are in credits on the Pro plan (1,000 per month, shared between the web app and the API). "Web" means done in the browser by the user, or by an agent at human pace with the user present. It does not mean unattended bulk scripting.

| Operation | Route | Web cost | API cost | Why |
|---|---|---|---|---|
| Concept image | API (`nano-banana` or `nano-banana-2-lite`) or the project's own image tool | 9 (Nano Banana Pro) | 3 to 9 | Cheapest model is API-only priced at 3; chains via `input_task_id` |
| Props, weapons, rocks, attachments: first generation | **API**, Smart Topology T2.5/T2 | 5 / 15 | 5 / 15 | Same price; batchable; polycount set at generation |
| Buildings, trees: first generation | **API**, 7.1 Standard + `should_remesh` | 20 / 33 | 20 / 30 | API textured is 3 to 5 cheaper; remesh included |
| Characters and heroes needing rerolls | **Web**, 7.1 set to **Standard** (not Ultra 2K) | 20 mesh / 33 textured, then 4 free retries | 20 / 30 per attempt | Retries make 5 attempts cost one |
| Remesh / polycount change | **In the API generation call** (`should_remesh` + `target_polycount`), or web Remesh | 0 | 0 in-call, 5 standalone | Never call the standalone endpoint |
| Rigging | **Web** (Humanoid, Quadruped, Smart Rig) | 0 | 5 (walk + run included) | Free, and more rig modes |
| Preset animations | **Web** (500+ library, Mixamo skeleton) | 0 per clip | 3 per clip | A 10-clip set saves 30 |
| Text to motion | Either (API `swift`) | 3 | 3 swift / 10 prime | Same price |
| Retexture / faction variants | **API** (`meshy-7`, `enable_original_uv`) | 10 | 10 | Same price, scriptable |
| Masked texture fixes, decals, seam healing | **Web** Texture Edit | unpublished | n/a | Web-only |
| UV unwrap | Either | 5 | 5 | Same price, at most 40k faces |
| Auto split into parts | Either | 10 | 10 | Same price |
| Download / format | Web (free, unlimited) or API `target_formats` at generation | 0 | 0 download, 1 convert | Avoid Convert; download API results within 3 days |
| Transfer to Godot | Official Godot bridge (Pro) | 0 | n/a | Sanctioned, no scripting |

Recommended default settings per asset type (always pin `ai_model`, use `target_formats: ["glb"]`, and set `enable_pbr: false` and `texture_resolution: "2k"` unless noted):

- **Rigged base bodies (humanoid / animal-folk):** Multi-Image to 3D with front, side and back views from one concept sheet; `meshy-7.1`; `geometry_resolution: "standard"`; `pose_mode: "a-pose"`; `image_enhancement: false`; `should_remesh: true`, `topology: "triangle"`, `target_polycount` about 20,000. No tails, capes, shells or held items. Rig and animate on the web. Pilot `meshy-6` with `remove_lighting: false` for painted light.
- **Modular attachments (horns, masks, shells, tails):** Image to 3D, `model_type: "smart-topology"`, `meshy-t2` (or `meshy-t2.5` if detail is lost). One isolated object per image on white. `target_polycount` 300 to 3,000. Mesh only (5), then Retexture (10) per variant.
- **Props and weapons:** Smart Topology `meshy-t2.5`, full length in frame, chunky proportions in the prompt, `target_polycount` 1,500 to 4,000, textured in one pass (15).
- **Environment pieces:** rocks and cliffs on `meshy-t2.5` at 500 to 6,000 faces with one shared style image per biome. Trees on `meshy-t2.5` at 2,000 to 8,000, with foliage as "large leaf clumps". Buildings on `meshy-7.1` Standard with `should_remesh: true` at 5,000 to 20,000, and Multi-Image when the back matters.
- **Hero / marketing models:** `meshy-7.1`, `geometry_resolution: "4k"` (single image) or `"2k"` (multi-image), `save_pre_remeshed_model: true`, 4K to 8K textures, and `enable_pbr: true` only for offline renders. Generate on the web to use the free retries.
